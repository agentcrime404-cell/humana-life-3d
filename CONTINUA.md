## Come si avvia
- Node 24 (usa `node:sqlite`). Server: `npm start` (script `scripts/play.mjs`), porta **3077**.
- **Due giochi, due server**: `server/index.js` → `createApp({dbPath,edition})`; `edition:''` = 2D (`scripts/play.mjs`, porta 3077, `data/humana.sqlite`), `edition:'3d'` = 3D (`scripts/play-3d.mjs`, porta 3079 o `PORT_3D`, `data/humana-3d.sqlite` o `DATABASE_PATH_3D`). Il server del 2D non apre più `/3d` e quello del 3D non apre il 2D (`EXPERIMENTAL=1` toglie il blocco). Il lanciatore/guardiano (3078) riguarda solo il 2D; il 3D non ha guardiano.
- Avvio del 3D: cartella Desktop `HUMANA life 3D` → `Avvio rapido HUMANA life 3D.cmd` (accende il suo server se spento e apre il gioco), `Ferma server 3D.cmd`. Per riavviare il 3D dopo modifiche al server: fermarlo e riavviarlo da lì (o terminare il processo `node ... scripts/play-3d.mjs`).
- QR del 3D: `npm run qr3d` (`scripts/qr-3d.mjs`) scrive `dist/qr-3d.png` e lo copia nella cartella Desktop `HUMANA life 3D`. Va rifatto se il PC cambia indirizzo.
- Firewall del 3D: lo apre l'utente con `Consenti telefoni di casa - 3D (firewall).cmd` (da amministratore, solo porta 3079, solo rete locale). Il 2026-10-04 sul PC non c'era nessuna regola firewall per il gioco.
- Lanciatore/watchdog `scripts/launcher.mjs` su porta 3078 (parte con Windows): riavvia il gioco se cade.
  Per riavviare il server dopo modifiche lato server: termina il processo `node ... scripts/play.mjs`, il watchdog lo riaccende in ~15 s.
- Test: `npm test` (48 test, devono passare tutti).
- APK: `npm run apk` (usa Java 21 portatile in `../tools/jdk-21*`: Java 27 di sistema rompe Gradle). Poi copia `dist/HUMANA.apk` in `Desktop/HUMANA life/HUMANA life.apk`.
- L'app Android carica il codice aggiornato dal PC (`client/loader.js`): le modifiche al client arrivano senza reinstallare. Alza la versione in `client/sw.js` (`humana-life-NN`, ora 73) quando cambi file del client.
- PC dell'utente: Intel Celeron N5095 + grafica integrata Intel UHD → il 3D deve restare leggero (obiettivo ≥30 FPS).
